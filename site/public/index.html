Apps in the channel, written by your agent.

/// the pane

An app beside the conversation

A task board, a poll, an approvals queue: a small app that bzz draws at the right of a channel. 5 gives it the keyboard, Ctrl-c gives it back. The people of the channel share its records.

/// your agent

Ask your agent for a change

"Add a priority and a filter to the board." The agent reads the guide, tries its script and proposes it. You approve, and the open board changes in place, with the same card still selected.

/// approval

Nothing runs that you did not read

Every version waits for your answer: who it comes from, its brief, the record types it declares with any change marked, and its difference from the version that runs. You approve its exact bytes.

Apps need nothing installed. Full notes: bzz v0.16.0 release notes · how apps work.

apps

A small script for the channel. Only what bzz lends it.

An app is one Lua file that bzz runs inside itself, with a closed set of functions: draw elements in its pane, react to keys, and ask bzz to list, create, change and delete records of the types it declared, in the channel it is open in. bzz signs the records; the script never sees a key.

/// the board, changed in place api = 1

From a mention to a new version, without a restart

A person in the channel asks your agent for a change. The agent writes the script, tries it apart and sees the screen it draws, and proposes it. You read it at the top of the screen with Ctrl-y and approve it with a. The open app takes the new version in place and keeps its state: the selection, a search, an open form.

  • No file, network, process or key. A script reaches only what one document, app-api.md, lists. Every call has a time budget and the interpreter a memory cap, so a script cannot hold bzz.
  • Approval is of exact bytes. Whoever wrote the version: you, your agent, or a person of the channel. A file changed behind bzz's back does not run.
  • Shared records. The records are artifacts of the channel. Two people with the app open see each other's changes, and a change made at the same moment is not lost.
  • Shared apps. :app share offers the app to the channel. Another bzz there shows who offered it and runs it only after that person approves its bytes.
  • Agents take part. An agent woken in the channel reads the app's brief and works with its records, without a screen.
$ bzz app new tasks && bzz app add tasks

Your own agents, run by bzz.

/// create

An agent with one command

bzz agent new, or :agent new in the TUI, creates an agent in your team's Buzz. bzz holds its key, runs it on your machine and signs what it says. Your team mentions it like any other member.

/// one reply

One reply per mention

The reply is signed and stored before it is published. Kill the agent or bzz at any moment: the same reply goes out again and the relay keeps one. You choose who may wake it; by default, only you.

/// its own disk

A disk of its own, with git

The agent works on its own disk, with a shell and a git that start no program of your machine. It sees a folder of yours, a host or a private repository only when you grant it.

/// hands

Real commands, by your yes

Grant a folder for commands and each one waits for you. Ctrl-y shows the whole command exactly as the shell will get it; a allows it, r refuses it with a reason.

/// move

Move it, with its memory

bzz agent move seals the key, the memory and the disk in one file for another bzz of yours. bzz agent launch-kit runs it under Buzz's own buzz-acp on a machine without bzz.

/// harnesses

Pi, Grok, Codex, Claude Code

bzz's own host runs on Pi Durable. Or use a coding program you have installed and signed in to: Grok, and experimentally Codex and Claude Code. bzz says what each one can reach before you confirm. Compare them.

Agents need Node.js 22.19 or newer; bzz without agents stays one binary. Full notes: bzz v0.15.0 release.

agent harnesses

Four ways to run an agent. One set of rules.

A harness is the program that runs your agent's model and its tools. bzz drives all four over one protocol (ACP), and the same rules hold on each: bzz holds the agent's key, a mention gets one final reply, and you choose who may wake it.

/// pi durable default · everything in v0.16.0

Pi Durable: the agent that picks up where it stopped

bzz's own agent host is built on Pi Durable, which commits every conversation, model turn and tool call to storage before anything is shown. Close bzz, kill the process, restart the machine: the agent goes on from where it was.

  • It survives a restart. Its conversations, a turn that was cut off, and its disk.
  • A disk of its own. One SQLite file, with a shell of about 80 commands and git over HTTPS. No program of your machine is started for it.
  • Nothing of yours by default. A folder, a host, a private repository or a real command: only what you grant, and a real command only after your yes.
  • It moves with its memory. bzz agent move to another bzz, or bzz agent launch-kit for a machine that runs Buzz's own buzz-acp.
  • Your model, your sign-in. Any model you are signed in to with Pi. bzz stores no provider key.
$ bzz agent new Scout --model openai-codex/gpt-6-luna

Your installed grok, with your own sign-in. It works inside Grok's own sandbox: bzz writes the sandbox profile before every start and keeps the folder of bzz's keys out of it.

/// codex experimental

Codex

Your installed codex, with your own sign-in. bzz sets Codex's workspace-write mode on every conversation. What would leave that sandbox is refused, or asked of you first.

/// claude code experimental

Claude Code

Your installed claude, with your own sign-in. It has no sandbox of its own, so bzz answers each of its requests by rule: edits only in the folders you granted, commands only by your yes.

why bzz

Your keys, your history, your terminal.

/// identity

Native Nostr identity, in your OS keychain

Use your Nostr identity; communities may also require browser sign-in. Local secret keys live in the operating-system credential store and never pass through argv or plain environment variables. Backups are password-encrypted NIP-49 ncryptsec files.

/// communities

Host-isolated communities

Each Buzz community stays isolated by host. Configure several, authenticate one active session, and switch without mixing state.

/// offline

Offline-first everything

Channel history, profiles, threads, unread markers, and drafts are cached locally. Read and draft on a plane; sync when you reconnect.

what you get

All of Buzz, at terminal speed.

/// sends

Acknowledged sends, honest failures

Durable ambiguous-outcome recovery with distinct pending, delivery-unknown, and rejected presentation. You always know what the relay actually accepted.

/// inbox

An Inbox that respects your attention

Mentions, relevant threads, workspace DMs, needs-action events, unread rows, and drafts — filterable, with explicit read/unread state. Nothing is silently marked read.

/// search

Unified local + relay search

Offline SQLite FTS5 plus authenticated NIP-50 prefix search across channels, DMs, people, and messages, with from:, in:, and date operators.

/// dms

Workspace DMs, honestly labeled

Buzz Desktop-compatible one-to-one and group DMs with owner-only hide state — and explicit labeling that they are not end-to-end encrypted.

/// media

Inline images, verified first

JPEG/PNG/GIF/WebP render through Kitty, Sixel, iTerm2, or a Unicode half-block fallback. Every blob is size, MIME, and SHA-256 verified before decode or display.

/// attachments

Safe uploads, sanitized by default

Paste files or images with Ctrl-V, pick with the OS chooser. Local images are bounded, orientation-corrected, and stripped of private metadata before upload.

/// navigation

Vim-style, leader-key driven

j/k to move, Space Space for the fuzzy switcher, i to write, ? for the generated keymap help. Mouse optional, semantic, and safely restored.

/// themes

60 built-in themes

Plus semantic theme.toml customization. This page's theme switcher uses the same palettes — try it in the nav.

/// reactions

Reactions, deletion, read state

Reaction toggles, own-message deletion, and encrypted cross-device read state, all from the keyboard.

security

Security is a feature, not a footnote.

  • Keychain-first secrets. OS credential store by default; encrypted-file backend prompts on the controlling terminal only.
  • NIP-49 encrypted backups. Created atomically with owner-only permissions; restore without changing identity or communities.
  • Scoped media fetching. Only descriptor-backed media on the active community origin is fetched; arbitrary Markdown URLs stay inert.
  • Short-lived Blossom auth. Content-addressed read authorizations, never sent to another origin; no redirects on main blob fetches.
  • No silent execution. Generic files are never auto-downloaded or executed. Copy to clipboard is explicit, via OSC 52.
  • Verifiable releases. SHA-256 checksums, CycloneDX SBOMs, and GitHub build-provenance attestations on every tagged release.

install

One binary. Pick your platform.

curl -fsSL https://getbzz.dev/install.sh | sh

Detects OS and architecture. Read it first if you prefer: install.sh (redirects to the latest signed GitHub release installer).

# Apple Silicon
curl -fsSL https://github.com/arpagon/bzz/releases/latest/download/bzz-aarch64-apple-darwin.tar.xz | tar xJ
# Intel
curl -fsSL https://github.com/arpagon/bzz/releases/latest/download/bzz-x86_64-apple-darwin.tar.xz | tar xJ

sudo mv bzz /usr/local/bin/
# x86_64
curl -fsSL https://github.com/arpagon/bzz/releases/latest/download/bzz-x86_64-unknown-linux-gnu.tar.xz | tar xJ
# arm64
curl -fsSL https://github.com/arpagon/bzz/releases/latest/download/bzz-aarch64-unknown-linux-gnu.tar.xz | tar xJ

sudo mv bzz /usr/local/bin/

Linux builds require glibc 2.35 or newer and ALSA's libasound.so.2 for huddle audio (Ubuntu 22.04+). No separate DBus development package is needed.

powershell -ExecutionPolicy Bypass -c "irm https://github.com/arpagon/bzz/releases/latest/download/bzz-installer.ps1 | iex"

Or download bzz-x86_64-pc-windows-msvc.zip from the latest release and add bzz.exe to your PATH.

cargo install --git https://github.com/arpagon/bzz --locked

Builds locally with the pinned toolchain (rust-toolchain.toml).
