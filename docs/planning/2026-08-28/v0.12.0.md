# bzz v0.12.0 — Themed agent status and coherent message selection

**Status:** Approved 2026-08-28

**Visual reference:** the segmented status bar in `charmbracelet/lipgloss`
`examples/layout/main.go` at commit
`77047a83c800e97d198ed80825c7cc698cc6808c`. Lip Gloss is visual inspiration
only; bzz remains independently implemented in Rust with Ratatui and its own
theme system.

## Release thesis

v0.12.0 is a bounded presentation release. It moves verified remote-agent
typing out of the writing dock and into a compact, animated, segmented status
bar. It also repairs message selection so the selected message reads as one
coherent item instead of a detached full-width stripe across only one row.

The release does not add a protocol, subscription, database migration,
configuration key, diagnostic identifier, publication path, agent runtime, or
local-agent hosting capability.

## User-visible result

A wide status bar should read like themed adjacent “nuggets”:

```text
 NORMAL  ◆ Fizz ⠹                              online  KITTY  ? help · q quit
```

The activity segment is deliberately small:

- one agent: `◆ Fizz ⠹`;
- several agents: `◆ Fizz +2 ⠹`;
- constrained width: `◆ 3 ⠹` or a cell-safe truncated first label;
- no valid activity: the segment is absent and its width returns to the center.

The Braille spinner occupies one terminal cell and advances only while a valid,
fresh typing projection is visible in the current scope.

Message selection must no longer resemble a floating horizontal status bar.
The selection treatment must stay visually attached to the selected message,
cover the correct rendered message block or use a compact gutter/accent, and
remain legible across avatars, grouped messages, wrapped bodies, reactions,
media, and every built-in theme.

## M0 — Preserve the semantic and privacy boundary

1. Reuse only the existing signed kind `20002` admission, verified-agent
   authority, selected-channel subscription, exact channel/thread scope,
   eight-second expiry, and matching-reply clearing behavior.
2. Continue to describe this source as typing activity. The compact spinner
   must not be documented or exposed as proof that a runtime is working,
   thinking, online, healthy, ready, progressing, or guaranteed to reply.
3. Keep kind `20002` transient, in-memory only, and excluded from durable
   storage, Inbox, search, unread state, copy, diagnostics identifiers, and
   OTel.
4. Publish no typing, observer, lifecycle, control, or agent event.
5. Do not add local-agent execution, discovery, process inspection, hosting, or
   runtime control. The status renderer may consume a normalized presentation
   value in a future release, but v0.12.0 has only the verified remote typing
   source.
6. Keep the deferred NIP-AO proposal in
   `docs/planning/2026-08-25/deferred-nip-ao-agent-activity.md` unapproved and
   unimplemented.

## M1 — Segmented status bar

1. Keep the status line one terminal row high and fill its complete width with
   the base status style.
2. Render adjacent segments in this order when space permits:
   - current mode;
   - verified-agent typing activity;
   - flexible notice/error area;
   - connection state;
   - graphics protocol;
   - help and quit hints.
3. Follow responsive priority rather than wrapping:
   - mode and urgent notice remain recoverable;
   - active-agent presentation remains compact;
   - help/quit and graphics are removed before essential state;
   - connection may disappear only at severely constrained widths;
   - no segment may overflow, split a wide Unicode cell, or create a second
     row.
4. Remove typing text and its cursor/hit-map offset from the composer. Reclaim
   the now-unused writing-dock row without allowing the dock to overlap the
   timeline.
5. Keep channel typing at channel scope and thread typing visible only for the
   exact open canonical root. Switching scope must not leave stale status text
   or animation.
6. Animate through a fixed one-cell Braille sequence at a bounded rate no
   faster than five frames per second. Request animation redraws only while an
   admitted typing projection is visibly active; idle sessions remain quiet.
7. Duplicate three-second typing refreshes must extend the existing expiry but
   must not create database work or reset the animation into flicker.

## M2 — Theme-compatible status nuggets

Add semantic highlight groups:

- `StatusAgent` for `◆ Fizz ⠹`;
- `StatusConnection` for the connection nugget;
- `StatusMedia` for the graphics-protocol nugget.

Requirements:

1. Built-in palettes derive all foreground/background colors from their
   existing semantic palette values. Do not copy Lip Gloss pink/purple values.
2. Existing `StatusBar` and `StatusMode*` behavior remains available.
3. Existing user `theme.toml` files that omit the new groups continue loading
   and receive safe built-in fallback styles.
4. Users may override or link each new exact, case-sensitive group with the
   existing strict theme parser. Unknown fields and unsafe color forms remain
   rejected or warned exactly as before.
5. Theme export and `docs/themes.md` document the new groups.
6. Every built-in theme must preserve readable contrast for the segmented bar;
   terminal-default channels remain supported.

## M3 — Coherent selected-message treatment

The current selected-message presentation can color a detached full-width row
while the message body remains visually separate. Replace that treatment with
a message-scoped selection.

1. Selection must identify exactly the keyboard/mouse-selected message and stay
   attached to its complete visible block.
2. Prefer a compact themed gutter/accent or a coherent block treatment over a
   bright full-width stripe on only the author/timestamp row.
3. Wrapped body lines must retain their message indentation; they must not jump
   beneath the avatar gutter or appear to belong to the next message.
4. Grouped consecutive messages must not produce orphan timestamp rows that
   look like separate separators.
5. Reactions, deleted messages, attachment rows, inline media placeholders,
   thread summaries, date separators, unread markers, and system events retain
   distinct semantics.
6. The selection remains discoverable in monochrome/limited-color terminals
   and across all built-in themes. Add a dedicated semantic highlight only if
   existing `SelectionMarker`/`SelectedRow` cannot express the coherent result;
   any new group needs the same backward-compatible fallback policy as M2.
7. Do not alter selected event identity, scrolling, thread opening, copy,
   reaction, read-state, or mouse hit-testing behavior.

The supplied production screenshot is review input only. It contains private
conversation data and must not be committed, copied into fixtures, logged, or
included in diagnostics, snapshots, documentation, or release assets. Tests
must use generated names and synthetic content.

## M4 — Tests and visual acceptance

Automated coverage must prove:

- the compact single/multiple-agent formats and Unicode-cell truncation;
- deterministic spinner frames and wraparound;
- no animation redraw while typing is absent or out of scope;
- bounded animation redraw while typing is visible;
- typing no longer changes composer content, cursor position, hit map, or dock
  height;
- wide and narrow status layouts remain exactly one row and retain required
  segments according to priority;
- existing custom themes load without the new groups;
- explicit overrides for each new status group apply correctly;
- selected-message styling covers or accents the intended message rather than
  a detached header row;
- wrapped/grouped messages preserve indentation and selection identity; and
- hostile labels and notices remain sanitized, bounded, and cell-safe.

Visual acceptance must use generated offline fixtures and review at least:

- wide, medium, and narrow terminals;
- no typing, one agent, and multiple agents;
- channel and exact-thread typing;
- normal, insert, command, and error/notice states;
- default bzz, one dark theme, one light theme, and one custom theme;
- selected plain, grouped, wrapped, reaction, and media messages.

No frame containing private user data may be retained.

## Explicit non-goals

v0.12.0 does not add:

- NIP-AO kind `24200` ingestion or decryption;
- human typing indicators or outbound kind `20002`;
- global/cross-channel agent activity;
- agent presence, readiness, progress, lifecycle, observer, or usage claims;
- local agents, child processes, ACP, keys, model/provider configuration, or
  runtime controls;
- schema migration, polling, history, archive, search, Inbox, unread, or
  diagnostics expansion;
- a second status row, status popover, agent dashboard, or clickable runtime
  controls; or
- a message/thread data-model or publication change.

## Completion criteria

v0.12.0 is complete only when the segmented themed status bar and coherent
message selection are implemented and visually verified, all semantic/privacy
invariants remain true, all required validation passes, documentation records
the evidence, and no private screenshot data or unrelated working-tree changes
enter the release commit.
