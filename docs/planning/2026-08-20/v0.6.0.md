# bzz v0.6.0 — Organized conversations and fast message actions

**Status:** Proposed

## Goal

Make active conversations easier to find, read, react to, and copy while
preserving bzz's local-first, offline/locked, human-send, Inbox, and identity
boundaries.

## Clean-room boundary

Other terminal clients are behavior-only research. v0.6 code, strings,
configuration, tests, fixtures, and artwork must be independently authored for
bzz. Do not copy or adapt GPL code, assets, screenshots, configuration grammar,
or tests.

## Scope

### 1. Channel organization

Add a private `ui.channel_sort` preference with three deterministic modes:

- **smart** (default): unread joined channels first, then channels with the
  newest validated local activity, then sanitized label/UUID tie-breaks;
- **recent:** joined channels ordered by local `last_event_at` descending;
- **alphabetical:** joined channels ordered by case-folded sanitized label and
  stable UUID tie-break.

`Space s` cycles modes and reports the active mode. The sidebar title always
names the current mode. Sorting is presentation-only: it must not alter channel
membership, unread/read state, subscriptions, finder ranking, stored order, or
network activity. Selection and scroll retain channel IDs rather than indexes
through mode switches, arrivals, and cache reloads.

### 2. Safe visual avatars

Render a small deterministic **local raster identicon** from the already
visible public key. Reuse the existing terminal image protocol selection
(Kitty/Sixel/iTerm2/half-block); retain the textual marker on unsupported,
small, disabled, locked, or failed image surfaces.

No `Profile.picture`, arbitrary URL, remote profile image, new avatar request,
or avatar cache is in scope. A real remote-avatar proposal would require a
separate security/privacy decision, SSRF/origin rules, bounded cache, explicit
opt-in, and a new ADR before implementation.

### 3. Practical safe Markdown

Extend the current sanitized renderer with independently authored presentation
for headings, quote gutters, ordered/unordered lists, task items, horizontal
rules, tables with bounded columns, inline code, and fenced code blocks with an
optional visible language label. Links remain inert visible text. Markdown must
never emit control sequences, execute code, fetch URLs, expand unbounded
content, or change message bodies/row ownership.

### 4. Explicit clipboard and logical message selection

- `y` copies the selected message's sanitized source text through OSC 52 only
  after the explicit user action; base64 output is bounded and control-free.
- `v` enters a local logical message-selection mode; movement changes a
  contiguous event-ID range and `y` copies those messages in chronological
  order. `Esc` cancels. This selection never marks messages read or changes
  Inbox state.
- The status/help states success, disabled/unsupported terminal, selected count,
  and bounded-size refusal without echoing copied contents.
- Native arbitrary character-range selection remains the terminal's job:
  `ui.mouse = "off"` disables bzz mouse capture for normal terminal selection.
  v0.6 does not pretend that logical message selection is a free-form character
  selection engine.

### 5. Faster reactions

Keep the existing action-menu flow. Add `r` on a selected timeline/context
message to open the existing reaction picker directly. Keys `1`–`8` select and
submit the displayed quick reactions; `Enter` remains available and `Esc`
cancels. No reaction is signed/published until an explicit picker choice passes
existing availability, ownership, and signer checks.

## Milestones

1. **Foundation:** typed channel-sort and clipboard configuration, presentation
   state for logical selection, independent clean-room ADR, and config/keymap
   validation/migration tests.
2. **Navigation:** one shared ordered channel view for sidebar render,
   keyboard/mouse movement, viewport reconciliation, and active-channel
   restoration; add `Space s`.
3. **Message surface:** local identicon preparation/fallback and measured
   Markdown blocks. Reuse generation-bound hit geometry; keep media decode and
   avatar preparation bounded/off the UI thread.
4. **Message actions:** OSC 52 writer, copy-range model, direct reactions, help,
   status feedback, and manual terminal-selection guidance.
5. **Closeout:** synthetic visual fixtures for every sort, graphics fallback,
   Markdown shape, copy boundary, and locked mode; benchmarks, relay journey,
   release-binary TUI run, documentation, audit, and release decision.

## Acceptance criteria

1. Switching all sort modes preserves the selected channel by ID and produces
   no read marker, subscription, or request.
2. Every avatar path is local/deterministic; no profile image field or URL is
   read for rendering. Kitty output is optional and safely falls back to text.
3. Arbitrary hostile Markdown is sanitized, bounded, deterministically measured,
   and cannot escape the terminal.
4. Copying is explicit, size-bounded, control-free, local, and does not print
   private copied text, alter reads, or publish. Multi-message order is stable.
5. `r` only opens a picker for a valid selected message; choosing a reaction
   preserves the existing human/signing boundary.
6. Existing pinned dependencies, MIT OR Apache-2.0 licensing, identity/profile
   isolation, Inbox semantics, locked mode, draft-only Codex boundary, and
   terminal restoration remain unchanged.
