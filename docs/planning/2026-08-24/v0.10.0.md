# bzz v0.10.0 — Agent-foundation reset

**Status:** Release candidate

v0.10.0 removes the retired one-shot Codex reply drafter before any managed-agent
support is designed. The former feature was a human-reviewed composition helper,
not a Nostr identity, ACP runtime, relay participant, or Buzz managed agent. Its
`agent` naming would permanently blur those trust and protocol boundaries.

## Product decision

Current bzz has no local agent runtime or assistant process integration.
Managed-agent work will be planned independently from the documented Buzz
Desktop model rather than grown from the old drafter.

This release:

1. deletes the Codex process wrapper, scratch/output policy, and public module;
2. removes `bzz agent`, TUI `:agent`, picker/review overlays, state, hit targets,
   cancellation hooks, and rendering;
3. removes the `LocalAgentConfig` model and Tokio process feature;
4. removes current configuration, security, troubleshooting, README, and E2E
   claims for the drafter;
5. automatically removes only the retired top-level `[[local_agents]]` key when
   loading an older configuration, while every other unknown field still fails
   closed;
6. marks the v0.3 release record and implementation plan as historical; and
7. adds `docs/how-agents-works-in-buzz.md`, a source-first description of Buzz
   Desktop managed agents that makes no bzz implementation recommendation.

## Non-goals

- No managed-agent implementation.
- No NIP-OA, NIP-AP, NIP-AE, NIP-AO, ACP, process pool, agent key, memory, or
  observer support.
- No autonomous publication or change to the human send boundary.
- No Buzz protocol-baseline update.
- No database migration or cache behavior change.
- No dependency upgrade.

## Compatibility and migration

The release is intentionally a minor-version removal before 1.0. Existing
v0.3-v0.9 configurations containing `[[local_agents]]` remain bootable: normal
`Config::load` strips that exact retired key and atomically rewrites the strict
configuration. It neither interprets nor executes the old values. Unknown keys
other than this one continue to fail closed.

There was no agent key, relay identity, database record, or durable approved
output to migrate. An empty historical `agent-scratch` directory, if present,
has no authority and can be removed by the user as ordinary local data.

## Release gates

- formatting and strict all-target Clippy;
- locked full tests, including all targets;
- legacy `[[local_agents]]` migration regression;
- release build and isolated `bzz check` migration smoke;
- CLI help contains no `agent`, `assistant`, or `codex` surface;
- `cargo deny check` and `cargo audit` retain the existing accepted baseline;
- Linux, Windows, Intel macOS, and Apple Silicon macOS CI;
- pinned Buzz relay integration remains green; and
- release archives, checksums, attestations, SBOM, Linux binary, keychain, and
  encrypted-file backend are verified after publication.

A manual Herdr acceptance run is not required for this removal-only release:
the deterministic TUI suites cover the remaining surfaces, and no new visual or
interactive flow is introduced. This is the explicit v0.10.0 release exception
allowed by `docs/releasing.md`.
