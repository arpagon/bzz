# bzz v0.9.0 — Private diagnostics and opt-in observability

**Status:** Implemented on `main`; release-candidate operator verification remains.

v0.9.0 is one release containing both approved plans, in dependency order:

1. [`local-connection-and-outbox-diagnostics.md`](local-connection-and-outbox-diagnostics.md)
   defines the typed event/redaction contract, private bounded journal, exact
   delivery presentation, metadata-only CLI, and support report.
2. [`opt-in-otel-client-observability.md`](opt-in-otel-client-observability.md)
   consumes only an explicit subset of that contract through a separate,
   default-off OTLP/HTTP protobuf exporter.

The local phase must remain independently useful and shippable when no remote
endpoint, credential service, network, or operator is available. The remote
phase cannot introduce another collection path, generic log forwarding,
historical upload, relay/outbox behavior, or an availability dependency.

## Release gates

- all acceptance criteria and approved decisions in both plans;
- strict formatting, Clippy, locked tests, dependency deny/audit, release build,
  `bzz check`, and platform CI;
- leak tests covering content, identities, credentials, paths, relay payloads,
  raw errors, config, environment values, and OTLP headers/body;
- fake OTLP status/redirect/timeout/queue tests and a controlled scoped-token
  `telemetry.test` canary;
- local diagnostics and TUI remain usable with telemetry off, missing, revoked,
  rate-limited, or unreachable; and
- release notes and validation evidence record local bounds, remote consent,
  exact delivery states, dependency changes, and canary cleanup.
