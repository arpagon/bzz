# bzz v0.11.3 — Verified-agent typing feedback

**Status:** Implemented and locally validated 2026-08-26; publication pending

**Prerequisite:** publish and verify v0.11.2 before tagging v0.11.3.

**Protocol baseline:** unchanged `block/buzz`
`9f55bf67456be10ff7c8238bf0d9e12e582848f6`

## Release thesis

v0.11.3 is a bounded conversation-feedback correction for verified remote
agents. While a Buzz managed agent is processing a channel or thread turn, its
harness already publishes signed ephemeral kind `20002` typing indicators every
three seconds. Buzz Desktop and Android reduce those signals to a short-lived
message such as:

```text
Fizz is typing…
```

bzz currently ignores the same live protocol signal. After an exact structured
agent mention, the user therefore sees no intermediate feedback until a
reaction or signed reply arrives.

v0.11.3 will subscribe to kind `20002` only for the selected channel, admit only
fresh correctly scoped signals authored by a currently verified remote agent,
and render a compact transient row:

```text
◆ Fizz is typing…
```

The indicator is presentation state, not a message and not runtime readiness.
It expires automatically, disappears when the matching signed reply arrives,
and is never persisted.

This release does not ingest NIP-AO kind `24200`, decrypt observer data, publish
human typing, control a runtime, or host an agent. The larger owner-private
observer proposal in `deferred-nip-ao-agent-activity.md` is deferred.

## Why this belongs in v0.11.3

This is an incremental correction to the existing v0.11 remote-agent
conversation surface:

- the agent identity and channel authority are already verified;
- the relay session and selected-channel subscription lifecycle already exist;
- kind `20002` is part of the pinned Buzz protocol baseline;
- `buzz-acp` already emits the signal while processing;
- the state is ephemeral, content-free, and bounded;
- no schema, key, encryption, configuration, process, or publication boundary
  changes; and
- Android/Desktop parity is achieved without claiming managed-runtime parity.

A v0.12 release should represent a new durable product capability or trust
boundary. A single interoperable typing row does neither.

## Source evidence

The exact pinned implementation establishes:

- `buzz-core` defines kind `20002` as an ephemeral channel typing indicator;
- `buzz-acp` signs an event containing an exact `h` channel tag, empty content,
  and optional NIP-10 `e` root/reply tags for thread scope;
- the harness refreshes typing every three seconds while the channel turn is in
  flight;
- ephemeral publishing is best-effort and intentionally drops under
  backpressure rather than blocking agent work;
- Buzz Desktop subscribes with kind `20002`, exact `#h`, `limit: 10`, and a
  ten-second overlap;
- Desktop accepts only events whose eight-second lifetime has not expired;
- Desktop clears matching typing state when a signed message by that author
  arrives and suppresses stale post-message indicators briefly; and
- relay conformance tests prove historical typing is not returned and live
  fan-out remains community-scoped even when two communities reuse the same
  channel UUID.

These are public relay behaviors. v0.11.3 does not read Buzz Desktop state,
Tauri commands, local archives, process receipts, logs, or keyring entries.

## Product decisions

### Receive verified-agent typing only

v0.11.3 consumes typing only when the event author is a current verified remote
agent for the active community and destination.

It does not add a general human typing feature. This keeps the patch tied to the
v0.11 managed-agent interaction gap and avoids silently expanding publication
or presence expectations for human users.

A later release may generalize the same bounded reducer to authenticated current
human participants after a separate UX/privacy decision.

### Do not publish human typing

bzz will not emit kind `20002` in v0.11.3. Composer edits remain local until the
existing explicit human send.

Receiving a public ephemeral channel signal does not justify broadcasting the
bzz user's keystroke activity. Outbound typing requires a separate explicit
privacy and rate-limit decision.

### Mirror Buzz timing semantics

Use the pinned behavior:

- agent refresh cadence: three seconds, controlled by the external harness;
- local display lifetime: eight seconds from the signed event timestamp;
- selected-channel subscription overlap: ten seconds, limit ten;
- future timestamps cannot extend visibility beyond eight seconds from local
  receipt; and
- a matching signed message clears the indicator immediately and suppresses
  stale same-scope typing for two seconds.

Missing refreshes simply expire. bzz never interprets expiry as completion,
failure, offline state, or runtime death.

### Keep channel and thread scope distinct

A kind `20002` event with only the exact `h` tag is channel-scoped. It may render
above the main channel composer.

A typing event with valid NIP-10 `e` tags is thread-scoped. It renders only when
the currently open context has the exact same canonical root coordinate.
Thread-only typing must never leak into the main channel indicator when context
is closed or a different thread is open.

Malformed, ambiguous, cross-channel, unknown-root, or over-deep coordinates are
ignored.

### Use verified identity presentation

The label comes from the existing sanitized profile projection and the stable
`◆` verified-agent marker. A name never establishes authority.

Fallback presentation uses the existing abbreviated pubkey helper only after
the author has independently passed current verified-agent admission. Avatars
are not required for this one-row correction.

### Typing is not readiness

`◆ Fizz is typing…` means only that bzz recently received a valid signed typing
indicator from Fizz's verified identity for this scope.

It does not prove:

- the model is configured or healthy;
- the external process remains alive;
- any tool is safe or progressing;
- a reply will be published;
- the active user is still eligible to invoke the agent; or
- bzz can start, stop, inspect, retry, recover, or cancel the runtime.

The indicator never changes verification, ownership, policy, eligibility,
membership, or send authorization.

## Protocol admission

Admit a candidate indicator only when all checks pass:

1. event kind is exactly `20002`;
2. serialized event, tag count, and individual tag lengths stay within existing
   bounded event limits;
3. Nostr event ID and Schnorr signature verify;
4. author is not the active human identity;
5. there is exactly one canonical `h` tag and it equals the selected channel
   UUID;
6. event timestamp has not already exceeded the eight-second TTL;
7. a future timestamp is clamped so it cannot produce more than eight seconds
   of local visibility;
8. author is a current verified remote agent in the active community;
9. destination authority is current: exact relay-signed `bot` membership for a
   non-DM channel, or the bounded v0.11.1 verified-owner DM exception;
10. optional NIP-10 root/reply tags form one unambiguous supported scope;
11. thread scope, if present, matches the exact currently open root before it is
    visible; and
12. the event is newer than the last matching signed message and outside the
    two-second post-message suppression window.

The event `content` is never displayed, copied, logged, indexed, diagnosed, or
persisted. Compatibility does not depend on it being empty even though the
pinned Desktop and harness emit empty content.

An agent can sign a misleading typing event. Verification proves authorship and
scope, not truthfulness. The eight-second expiry bounds the effect.

## Subscription lifecycle

Add a dedicated selected-channel subscription rather than kind `20002` to the
global stream:

```json
{
  "kinds": [20002],
  "#h": ["<selected-channel-uuid>"],
  "since": "<now-minus-10-seconds>",
  "limit": 10
}
```

The placeholder `since` is encoded as an integer on the wire.

Requirements:

- open only while an unlocked authenticated community has a selected channel;
- replace it atomically on community/channel switch;
- close it on lock, disconnect, cached-only transition, or shutdown;
- replay it through the existing desired-subscription registry after reconnect;
- use a fresh ten-second overlap on each new selected-channel subscription;
- quarantine terminal `CLOSED` responses until reconnect or channel change;
- never issue HTTP/backfill/search queries for typing;
- never add typing to startup archive backfill; and
- never retry in a hot loop.

The relay may return EOSE with no historical rows because kind `20002` is
ephemeral. That is normal.

## Transient state model

Keep a small in-memory map keyed by:

```text
(agent_pubkey, scope)

scope = selected channel | exact open thread root
```

Each entry contains only:

- agent pubkey needed to join the existing verified profile view;
- normalized scope;
- signed source timestamp;
- local first-seen ordering timestamp; and
- expiry deadline.

Bounds:

- at most 16 simultaneous verified-agent typing entries;
- at most one channel entry and one thread entry per agent;
- at most ten admitted candidates per subscription overlap;
- event-ID replay deduplication uses the existing bounded community cache;
- nearest-deadline expiry scheduling, not a per-frame database query;
- one coalesced redraw only when visible membership changes; and
- duplicate three-second refreshes update expiry without reallocating labels,
  writing SQLite, or rebuilding Inbox/search/read state.

Clear all entries on channel/community switch, lock, disconnect, disablement of
the active runtime, or shutdown. Nothing survives restart.

## Completion and stale-signal suppression

When an admitted kind `9` or `40002` message arrives:

1. verify/store it through the existing authoritative message path first;
2. resolve its signed author and canonical channel/thread scope;
3. clear only that author's matching typing entry;
4. record an in-memory two-second suppression deadline for that exact
   author/scope; and
5. ignore delayed typing events whose signed timestamp is not newer than the
   message or which arrive during that suppression window.

Do not clear:

- another agent's indicator;
- the same agent in another scope;
- a channel indicator for a thread-only message;
- a thread indicator for another root;
- typing after a reaction or system event; or
- any state because a local outbox message was merely queued or rejected.

A relay duplicate of the reply remains a no-op after the first clear.

## TUI presentation

### Placement

Reserve no permanent row. When active, render the indicator in the existing
conversation activity/composer boundary so it does not become part of timeline
history:

```text
◆ Fizz is typing…
```

It must not move timeline selection or become a selectable/copyable message.
When the entry expires, the normal composer/status layout returns.

For an open context, render matching thread typing adjacent to the context
composer/status area, not in the main timeline and not under a thread root
summary.

### Multiple verified agents

Use deterministic first-seen order and bounded wording:

```text
◆ Fizz and ◆ Honey are typing…
◆ Fizz, ◆ Honey, and 2 others are typing…
```

At most two names appear in the compact row. Exact punctuation and fallback
labels remain sanitized and width-aware.

### Narrow and monochrome behavior

- the `◆` marker carries verified-agent meaning without color;
- truncate labels by terminal cell width, never byte offsets;
- preserve the final `is typing…` meaning when width permits;
- collapse multiple agents to `2 verified agents are typing…` at narrow widths;
- render nothing below the existing minimum supported terminal fallback; and
- avoid shimmer, animation, per-frame ellipsis changes, or periodic redraws.

### Interaction isolation

The indicator has no hit target and does not affect:

- timeline/context selection;
- scrolling or live-edge acknowledgement;
- composer focus, cursor, structured mentions, attachments, or drafts;
- mouse routing;
- context opening/closing;
- copied message text;
- search, Inbox, unread, read state, or thread summaries; or
- status/error precedence for send failures and connectivity.

If the terminal has room for only one transient status, actionable local errors
and acknowledged-send state take precedence over typing.

## Persistence and privacy

v0.11.3 adds no migration, table, index, config section, key, credential, file,
or cache record.

Kind `20002` must be handled before ordinary durable event ingestion. Add a
store-level rejection guard so a routing regression cannot insert it into the
generic event archive.

Typing data is excluded from:

- message/event persistence;
- Inbox and search;
- unread/read-state calculations;
- drafts and outbox;
- clipboard/copy output;
- local diagnostic journals and support reports, except optional content-free
  aggregate admission/rejection counters;
- OTel under every configuration;
- snapshots containing real identities; and
- release fixtures containing production data.

Diagnostics, if added, may expose only fixed enums and aggregate counts. They
must not contain agent names, pubkeys, owners, event/channel/community IDs,
relay URLs, tags, timestamps, content, or scope coordinates.

## Architecture

Expected changes remain small:

```text
src/agents/
  typing.rs             pure admission/scope/TTL reducer

src/realtime/
  subscriptions.rs      selected-channel typing filter

src/store/events.rs     explicit kind-20002 durability rejection

src/ui/
  typing.rs             compact width-aware presentation
```

`App` owns only subscription lifecycle, transient reducer integration, and
redraw scheduling. Protocol parsing and rendering must not collapse into the
network event arm.

No module may import process spawning, ACP, NIP-44 observer, memory, usage,
provider, or agent-key APIs.

## Deterministic test matrix

### Admission

- valid verified agent, selected channel, fresh channel scope;
- valid direct and nested thread coordinates for the open context;
- invalid signature or event ID;
- author is an ordinary profile, human member, or unverified bot;
- verified agent from another community;
- removed/stale bot membership;
- valid owner-controlled DM participant and invalid non-owner candidate;
- missing, duplicate, malformed, or wrong `h` tag;
- malformed/ambiguous `e` root and reply markers;
- wrong/closed thread root;
- expired event;
- far-future timestamp clamped to local eight-second maximum;
- duplicate event ID and repeated refresh; and
- arbitrary bounded content ignored without display or persistence.

### Reduction

- first signal creates one entry and one redraw;
- three-second refresh extends expiry without duplicate row;
- no refresh expires at eight seconds;
- nearest deadline handles multiple agents deterministically;
- matching signed reply clears only exact author/scope;
- delayed pre-reply signal cannot resurrect the row;
- new post-suppression signal can start a later turn;
- reaction/system/deletion events do not falsely complete typing;
- channel switch and reconnect clear old scope; and
- lock/shutdown leaves no transient state.

### UI

- one and multiple verified agents;
- sanitized profile and abbreviated-key fallback;
- wide channel and open-context placement;
- thread-only typing absent from closed main timeline;
- narrow deterministic collapse;
- monochrome semantics;
- composer cursor, draft, mention completion, attachments, status errors, and
  mouse hit map unchanged;
- no copied typing text; and
- expiry causes no selection/scroll jump.

### Non-interference and resources

- kind `20002` rejected by durable store API;
- no event/message/search/Inbox/unread/read-state row;
- no diagnostics or OTel identifiers/content;
- sustained three-second refresh across 16 agents remains memory bounded;
- ignored/duplicate signals do not redraw or write;
- selected-channel replacement does not leak subscriptions;
- terminal `CLOSED` does not hot-loop; and
- input, media staging, channel switch, and acknowledged send retain priority.

## Release gates

### Local deterministic gates

- `cargo fmt --all -- --check`;
- strict locked all-feature/all-target Clippy;
- locked all-target tests and benchmark smoke;
- protocol/property tests for bounds, spoofing, TTL, and coordinates;
- store-level ephemeral rejection and no-write observation;
- `cargo deny check` and `cargo audit` against the accepted baseline;
- release build, exact `bzz --version`, and isolated `bzz check`;
- wide/narrow sanitized visual review; and
- quiet idle and clean terminal exit.

### Cross-platform gates

- Linux, Windows, Intel macOS, and Apple Silicon builds/tests;
- timer/clock tests do not depend on wall-clock sleeps;
- Unicode/cell-width rendering is target-independent; and
- no platform-specific process, keychain, or graphics behavior is introduced.

### Pinned relay gates

- exact kind `20002` + `#h` live subscription;
- historical EOSE returns no typing requirement;
- deterministic verified agent signal renders;
- ordinary/unverified author does not receive an agent marker;
- channel and thread scopes remain distinct;
- same UUID across communities remains isolated;
- signed reply clears typing;
- stale/duplicate/future signals remain bounded; and
- reconnect and terminal rejection do not churn.

### Publication gates

- v0.11.2 is already published and verified;
- tag resolves to the fully validated v0.11.3 commit;
- archives, checksums, SBOM, and provenance verify;
- downloaded Linux binary reports v0.11.3 and passes isolated `bzz check`;
- native-keychain and encrypted-file identity smoke remain green;
- no production typing/event data exists in artifacts or evidence; and
- verification documentation records exact workflow and artifact results.

## Explicit non-goals

v0.11.3 does not:

- publish human or agent typing from bzz;
- display typing for ordinary human participants;
- persist typing or reconstruct it after restart;
- treat typing as readiness, presence, health, progress, or guaranteed reply;
- modify agent verification, ownership, policy, eligibility, or membership;
- change message publication, mentions, drafts, outbox, ACK, Inbox, unread,
  search, copy, or thread summaries;
- ingest/decrypt/archive NIP-AO kind `24200` observer frames;
- publish observer controls or owner commands;
- ingest NIP-AE `30174`, NIP-PMA `30179`, or usage `44200`;
- create, host, wake, start, stop, retry, inspect, recover, or cancel an agent;
- import or store an agent private key;
- spawn ACP, model, provider, tool, MCP, or custom harness processes;
- read Buzz Desktop private state or APIs;
- add a schema migration or configuration setting; or
- claim Android/Buzz Desktop feature parity beyond the bounded typing signal.

## Definition of done

v0.11.3 is complete only when:

1. a fresh signed kind `20002` from a current verified destination agent renders
   `◆ <name> is typing…` in the exact selected channel or open thread;
2. the row expires at eight seconds, refreshes without duplication, and clears
   on the matching signed reply;
3. stale, delayed, malformed, spoofed, unverified, removed, cross-community,
   and wrong-scope signals cannot render or persist;
4. thread-only typing never appears as channel-level typing;
5. kind `20002` cannot enter durable storage, Inbox, search, unread, read state,
   copy, diagnostics content, or OTel;
6. bzz publishes no typing or observer/control event;
7. no NIP-AO decryption, runtime control, local hosting, agent key, ACP, model,
   tool, memory, usage, or provider surface is added;
8. duplicate/ignored traffic produces no SQLite/redraw hot loop;
9. wide, narrow, context, reconnect, lock, idle, and terminal cleanup behavior
   are verified; and
10. deterministic, pinned-relay, cross-platform, privacy, artifact, and
    publication gates pass at the tagged commit.
